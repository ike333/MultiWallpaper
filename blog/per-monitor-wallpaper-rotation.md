# 我在多显示器上实现「每个屏各自轮播壁纸」，踩了 9 个坑才搞定

> 这是一个 Windows 原生小工具的开发手记：没有浏览器、没有 Python、没有 base64，
> 纯 Win32 API + 注册表，让多台显示器**各自拥有独立的壁纸序列**，按分钟自动轮换。
> 文章重点不在"怎么用"，而在"为什么这么难"——尤其是最后那个连我自己都找了一下午的 `WallpaperStyle` 真凶。
> 工具已开源：[ike333/MultiWallpaper](https://github.com/ike333/MultiWallpaper)。

---

## 写在前面：试了十几种软件，没有一个对味

动手开发之前，我在网上找壁纸轮换软件找了一整个下午。

开源的、商业的、免费 trial 的，**前前后后装了不下十几种**——什么 Wallpaper Changer、DisplayBuddy、Wallpaper Engine 的各种"多屏模式"、各种"不同壁纸轮换器"，名字都忘了，只有一个感受刻得很深：

**没有一个能做到"每台屏一个自己的播放列表，各自独立计时"。**

不是不行，是"不够用"。它们能做到的，无非是这两种：

- **全屏幕同图轮换**：所有显示器一起切，永远是同一张。三块屏看着像，其实是"一张大图"或"三块同图"，我的三块屏节奏不一样（竖屏序列短、横屏序列长），根本不对味
- **固定不同图 + 定时整体切换**：每块屏能配不同的图，但切换是"整组"一起切，不能"竖屏 30 分钟转一圈、横屏 8 小时转一圈"这种各自节奏

我想要的就一句话：**"竖屏放我的 2 张，横屏放另外 16 张，各转各的，互不干扰。"**

试了这么多，没有一款能让我勾完、点完"应用"、然后三块屏各按各的节奏安静地转下去。要么序列被锁死同图，要么一热插拔屏配置就崩，要么"立即切下一张"点了没反应，要么——最要命的——**切换完屏幕根本没变**（这个后面坑 8、坑 9 会专门讲，几乎所有软件都栽在这）。

最后我放弃了。花了一下午找了十几款，不如自己写一个。

> 这不是"轮子造多了"，而是"现有轮子没有一条辐条是我需要的"。下面是这段折腾的完整记录。

## 一、需求：三台屏，三套节奏

我的桌面是三台显示器：

| 编号 | 设备 | 分辨率 | 位置 |
|---|---|---|---|
| 显示器 1（主） | `\\.\DISPLAY5` | 1920×1080 | 居中，(0, 0) |
| 显示器 2 | `\\.\DISPLAY1` | 1600×900 | 左侧，(-1600, 104) |
| 显示器 3 | `\\.\DISPLAY4` | 900×1600（竖屏） | 右侧，(1920, -258) |

需求很简单：

- 目录里有 18 张图，**图 1-2 只在显示器 3 上轮播，图 3-18 只在显示器 1、2 上轮播**
- 每张图有独立的"显示时长（分钟）"，比如某张停 10 分钟、某张停 30 分钟
- 各屏**独立计时**：显示器 3 的序列短（2 张），它 30 分钟转一圈；
  显示器 1/2 的序列长（16 张），各自 16×30 分钟转一圈，互不牵制
- 程序常驻托盘，关掉设置窗口轮换不停

听起来就是"给每个屏配个播放列表"，对吧？

**就是这句话，让市面上所有软件都答不上来。** 它们要么"全屏幕同一序列"，要么"不同图但整组一起切"，
就是给不出"各屏各自序列、各自节奏"。所以没有第二选择——自己写。

写代码之前，我又在网上搜了半天"怎么让每块屏显示不同壁纸"，找到的答案清一色是：
"写注册表 `Device--DISPLAYn` 的 `Transitions`，然后调 `RefreshDesktop`，完事。"

照着做，**屏幕纹丝不动**。这就是这篇文章要讲的核心——
**那些"现成答案"差的那一步，恰好是关键。**

## 二、技术选型：先排除掉不"标准"的做法

第一版我偷懒用了浏览器 + Python：一个 HTML 页面当 UI，Python 后台计时切壁纸。
用了两天就崩了：

- 标签页切后台被浏览器**节流**，计时全乱；关页面就停
- 图片经 base64 走 HTTP 传给 Python，每次切换还写临时文件
- 没法常驻系统、没法开机自启

所以重写成 **C# / .NET 8 WinForms**，直接调 Win32 API。零第三方依赖，
编译出来一个几百 KB 的 exe。这也是本文后面所有代码的基础。

## 三、先搞清楚 Windows 到底怎么渲染多屏壁纸

这是我绕了最久的一段路。先把结论放前面（详细实测在文末附录）：

### 3.1 桌面只认"一张图"

无论你在"个性化"里选了"每个显示器一张不同壁纸"，还是幻灯片放映，
**Windows 10 桌面窗口实际渲染的来源，始终是一张覆盖整个虚拟桌面的壁纸文件**。

- 虚拟桌面 = 所有显示器外接口的并集包围盒。我这三台屏合起来是 4420×1600
  （原点在 -1600, -258）
- 系统把这张图转码缓存为
  `%APPDATA%\Microsoft\Windows\Themes\TranscodedWallpaper`，
  并让 `HKCU\Control Panel\Desktop\Wallpaper` 指向它
- "每个屏一张不同图"的体感来自：系统把各屏的图**按它们在虚拟桌面中的位置拼进
  这张主壁纸**，各屏只显示自己那一块。看起来"独立"，底层还是一张大图

### 3.2 写注册表 ≠ 屏幕会变（关键误解）

`HKCU\Control Panel\backgrounds\Device--DISPLAYn\Transitions` 里存着"该屏当前该显示哪张图"。
网上的教程都停在这一步："把各屏的图写进各自的 Transitions，然后刷新桌面。"

我在真实机器上做了个受控实验：

```
实验前 TranscodedWallpaper 修改时间 = 19:15:08
（写 3 个设备键 + SPI_SETDESKWALLPAPER(0) + 广播 WM_SETTINGCHANGE）
实验后 TranscodedWallpaper 修改时间 = 19:15:08   ← 纹丝不动
```

也就是说：**设备键只是"配置记录"，系统不会因为你改了它而重新渲染。**
要屏幕立刻变，必须更新"主壁纸"这条路（即那张 4420×1600 的图 + 转码缓存）。

### 3.3 `WallpaperStyle`：几乎没人提到的最后一个开关

`HKCU\Control Panel\Desktop\WallpaperStyle` 决定"主壁纸文件怎么映射到屏幕"：

| 值 | 含义 | 多屏下每屏的行为 |
|---|---|---|
| 0 | 居中 | 每屏显示整图（居中留边） |
| 1 | 平铺 | 每屏平铺整图 |
| 2 | 拉伸 | 每屏拉伸整图 |
| 6 | 适应 | 每屏等比适配整图 |
| 10 | 填充 | 每屏等比裁剪整图（**取中央块**） |
| **22** | **跨所有显示器** | 一张图铺满虚拟桌面，各屏裁自己那块 |

默认系统常停在 **10（填充）**。在这个样式下，把 4420×1600 的长图"填充"到
1920×1080 时，系统会**居中保留一块宽高比匹配的区域**——恰好是长图的中央。
结果就是**三块屏全显示中间那块**。这是我最后才定位到的真凶（坑 9）。

## 四、最终方案：一条干净的落盘管线

想明白机制后，程序每次"应用一轮"做的事：

```
各屏当前图（来自各自序列游标）
      │  按虚拟桌面布局 DrawImage（32bppArgb 画布，未配图的屏留黑）
      ▼
%LOCALAPPDATA%\MultiWallpaper\per-monitor-current.png   （虚拟桌面尺寸 4420×1600）
      │  SystemParametersInfoW(SPI_SETDESKWALLPAPER, path, 0x40)
      ▼
系统转码 → TranscodedWallpaper，Desktop\Wallpaper 指向它
      │  把 WallpaperStyle 写成 22（跨所有显示器）
      ▼
各屏裁出自己在虚拟桌面中的那块 → 屏幕上各显其图
      │  同时把各屏当前图写进 Device--DISPLAYn\Transitions（与实际显示一致）
      ▼
注册表 / 屏幕 / 主壁纸文件 三者对齐
```

要点：

- **拼 PNG 而不是 JPEG**：无损，避免每张图反复 JPEG 有损压缩累积劣化
- **32bppArgb 画布**（坑 4）：24bppRgb + GDI 在部分系统上保存后全黑
- **没配图的屏留纯黑**：比"卡在上一张"更容易被察觉和修正
- **同步写设备键**：让"个性化设置"里看到的各屏背景与实际一致，重启也不跳回旧图

## 五、按显示器分组：各屏独立节奏

数据模型必须"以显示器为主体"。第一版我是按"图片"遍历的——每张图到点后写进它勾选的所有屏，
结果三块屏节奏被图片顺序锁死，永远同图。改成按屏分组后：

```
每台显示器 i：
  序列 Seq_i = [ 勾选了屏 i 的图片，按表格顺序 ]
  游标 cursor_i
  剩余 remaining_ms_i = 当前图分钟数 × 60000

Tick（后台 Timer，每秒）：
  各屏 remaining_ms_i -= 1000
  到期的屏：cursor_i 前进一格，重算 remaining
  ApplyPerMonitor()：所有屏取自己序列当前图 → 走上面的落盘管线
  下次 Tick 间隔 = min(各屏 remaining_ms_i)
```

我这三台屏的实际节奏：显示器 3 序列 2 张、每 30 分钟转一圈；显示器 1/2 序列 16 张、
各自独立 16×30 分钟。互不影响。

## 六、九个坑，逐个说（本文精华）

以下按开发顺序。每个都是"现象 → 根因 → 修复"。

### 坑 1：不存在的 P/Invoke，有配置就崩

第一版写了 `ChangeWallpaper`、`SetCurrentTimeOfDay`、`StopSlideshow` 三个 API，
来自某些老文章。它们在 `user32.dll` 里**根本不存在**，第一次调用就抛
`EntryPointNotFoundException`，而且发生在 UI 线程外，日志里看不到异常，
进程直接挂掉。

**修复**：全删。多屏走"拼主壁纸 + 写设备键"。
**教训**：任何 P/Invoke 先验证导出表再写。

### 坑 2：设备子键名拼错（单横线 vs 双横线）

真实键名是 `Device--DISPLAYn`（**双横线**）。早期代码拼成单横线或带前缀反斜杠，
写进了一个"无人在乎"的孤儿键。

**修复**：设备名 `\\.\DISPLAY1` 去掉前导 `\`、`.`、`\`，子键名 = `"Device--" + dev`。

### 坑 3：中文路径变乱码

图片目录带中文（`E:\My Picture\桌面背景`），保存再加载后路径变成问号串。
根因是 `File.WriteAllText` 用了系统默认代码页（GBK 机器），把 UTF-8 的 JSON 写坏了。

**修复**（`ConfigStore.cs`）：读写一律显式 `new UTF8Encoding(false)`（无 BOM），
JSON 加 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`。
**教训**：Windows 上持久化中文路径，永远显式指定编码。

### 坑 4：拼合大图全黑

第一次拼合时输出了一张**全黑**的图，一度怀疑磁盘/权限。
根因是用了 `Format24bppRgb` 画布 + `Graphics.DrawImage`，GDI 在某些 Windows 版本上
不会把数据正确落到 24bpp 位图。

**修复**：画布改 `Format32bppArgb`，输出 PNG。
**验证**：不要只看"文件生成了"，**像素采样**各屏区域中心点，确认非黑且颜色符合该屏配置的图。

### 坑 5：按"图片"轮换 → 三屏永远同图

用户反馈"三个显示器的图片都是 1"。根因是第一版按图片遍历，所有屏被图片顺序锁死。

**修复**：改按显示器分组，每屏独立游标 + 独立计时（见第五节）。
**教训**：多设备独立轮换，数据模型必须以设备为主体。

### 坑 6：「刷新显示器」后 D3 的勾选神秘消失（位置索引不稳定）

图 1-2 勾了显示器 3，点"保存配置"或"立即应用"后点"刷新显示器"，
D3 的勾选就没了。

根因：旧配置把显示器存成 **0-based 位置索引**，而每次枚举都按"主屏优先 + Left/Top"
重排重新编号——拔插过屏、主屏标志一变，同一物理屏的编号就变，旧索引指向错屏或查无此屏。

**修复**（`OnRefreshMonitors`）：刷新时先用**旧**枚举读回勾选，重新枚举后经
`旧Index → 设备名 → 新Index` 映射对齐，再重填网格。
**说明**：中途试过把配置直接改成存设备名 + 迁移，后来**回退**了——设备名在驱动重置/
多显卡重排时同样会变，且让 UI 与运行时时序复杂化。保留"位置索引存盘 + 刷新时按设备名对齐"，够用且简单。

### 坑 7：DataGridView 复选框"值形态"误读（最隐蔽）

坑 6 修完后，用户发现**只有**"图 1、2 → 显示器 3"这种手点勾选会被刷新丢掉，
走"全选"按钮设置的正常。判断："应该是程序的问题，不是设备名的问题。"

用一个 30 行最小探针证实根因：

- 勾选列设了 `TrueValue = 1, FalseValue = 0`（int）
- **用户手点**复选框时，WinForms 提交的是列的 TrueValue，即 **int 1**
- "全选"按钮写的是 **bool true**
- 而读取代码 `v is bool b ? b : (v != null && v.ToString() == "True")` 只认 bool 和 "True"，
  **把 int 1 判成"未勾选"**

探针输出：

```
img1  值类型=Int32 值=1      → 现有判定 False   ← 手点勾选被误判
img3  值类型=Boolean 值=True  → 现有判定 True    ← 程序写入的 bool 正常
```

**修复**：`IsCellChecked()` 统一兼容 bool / int(≠0) / 字符串("True"/"1")。
**教训**：WinForms 数据格子的 `Value` 实际类型取决于列的 True/FalseValue 和写入路径，
读取端永远不能假设只有一种形态。

### 坑 8：误以为"写注册表 + 刷新"就能让各屏独立渲染

删掉拼合逻辑、改成只写 `Device--DISPLAYn\Transitions` 后，屏幕完全不动——
"实际屏幕还是之前那张"。

**根因**（见 3.2 受控实验）：Windows 10 多屏桌面由"一张虚拟桌面主壁纸"驱动，
`Device--DISPLAYn` 键只是配置记录，**只改它不更新主壁纸文件，系统不会重新渲染**。
网上大量教程止步于此，在"系统已处于每显示器模式且 UI 路径会顺带更新主壁纸"的场景下
**看起来**能用，但程序化直接写是无效的。

**修复**：恢复"生成主壁纸"这一步（见第四节管线），并同步写设备键保持一致。

### 坑 9（真凶）：`WallpaperStyle=10` 让三屏都显示"中间那块"

坑 8 修完后，各屏内容"还是和原来一样"：主屏显示中间图+左图一半，左屏和主屏一样，
右屏显示合成图中段。

**根因**：主壁纸已经是正确的 4420×1600，但 `WallpaperStyle=10`（填充）。
填充语义是"把**整张**主壁纸适配到**每个**显示器"——4420:1600 的长图适配到 1920×1080，
系统居中保留宽高比匹配的一块，**恰好是长图中央** → 三屏全显示中间那块。

**修复**：`SetPerMonitorWallpaper` 设主壁纸后，把 `WallpaperStyle` 改为 **22**、
`TileWallpaper=0`，再广播刷新。于是左屏取左侧、主屏取中间、右竖屏取右侧，各显其图。

```csharp
using var desk = Registry.CurrentUser.OpenSubKey(@"Control Panel\Desktop", writable: true);
desk?.SetValue("WallpaperStyle", 22, RegistryValueKind.String);
desk?.SetValue("TileWallpaper", 0, RegistryValueKind.String);
RefreshDesktop();
```

**教训**：Windows 壁纸"样式"和"主壁纸文件"是两个正交配置。换了图不换样式，
行为就完全不是你以为的那样。

## 七、使用与构建

```bash
cd MultiWallpaper
dotnet build -c Release
# 产物: bin\Release\net8.0-windows\win-x64\MultiWallpaper.exe
```

单文件免运行时：

```bash
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true
```

1. 运行 exe，选一个图片目录（png/jpg/jpeg/bmp/webp/gif）
2. 表格里每张图勾选要显示的显示器，填显示时长（分钟）
3. **▶ 立即应用** 开始轮换；**💾 保存配置** 存到 `%APPDATA%\MultiWallpaper\config.json`
4. 托盘菜单"立即切换下一张"让各屏同步前进一格；关闭设置窗口轮换不停

## 九、几点边界与说明

- 需要 **Windows 10 1809+**（每显示器独立壁纸机制）；更早版本三屏会显示同一张主壁纸
- 分辨率/布局变化后主壁纸尺寸会失配，点一次"刷新显示器 + 立即应用"重新生成
- `\\.\DISPLAYn` 设备名在驱动重置/多显卡重排时可能重排（Win32 没有公开"持久显示器 ID"），
  本程序在刷新后会把旧配置映射到新编号，极端场景下用户重新勾一次即可
- 只改桌面，不影响锁屏界面
- 程序会在 exe 同目录写 `MultiWallpaper.log`（纯文本日志，排障用）

## 附录：怎么验证"屏幕真的变了"（别再只信代码跑通）

我排坑时最有效的手段，都是**在真机上做能观察到中间产物的受控实验**：

1. 看 `TranscodedWallpaper` 的**修改时间**——主壁纸管线有没有真的触发
2. **像素采样**合成图各屏区域中心点——各屏是不是真放了各自的图（而非全黑/同一块）
3. 读 `WallpaperStyle` 当前值——确认映射语义对
4. UI 回归：勾选（手点 / 全选）→ 保存 → 刷新显示器，勾选不丢；"立即切换下一张"各屏各自前进

这套"验证清单"我放进仓库 `docs/DEVELOPMENT.md` 末尾了，做同类问题的排查可以直接抄。

`WallpaperStyle=22`。希望这篇能帮你少走我一下午的路。
